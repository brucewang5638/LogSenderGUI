# 代码结构设计思路

本文档旨在详细解释 LogSenderGUI 项目的代码结构，帮助开发者快速理解项目的设计思路和各个模块的功能。

## 顶层目录结构

```
LogSenderGUI/
├── app/                  # 核心应用代码
├── docs/                 # 项目文档
├── .github/              # GitHub Actions 工作流配置
├── rawdata/              # 存放原始数据
├── rawdata_processed/    # 存放处理后的数据
├── .gitignore            # Git 忽略文件配置
├── config.py             # 全局配置文件
├── main.py               # 应用主入口
└── requirements.txt      # Python 依赖库列表
```

### `app/`

这是项目的核心目录，包含了所有的业务逻辑和界面实现。我们采用分层设计的思想，将不同的功能拆分到不同的模块中，以实现高内聚、低耦合的目标。

-   **`ui_builder.py` (UI 构建层)**
    -   **作用**: 专门负责创建和布局所有的图形用户界面（GUI）元素，比如窗口、按钮、文本框等。
    -   **设计思路**: 将界面的定义与业务逻辑完全分离。这样做的好处是，当我们需要修改界面样式或者布局时，只需要关心这个文件，而不用担心会影响到其他逻辑。它就像是应用的“外观设计师”。

-   **`app_controller.py` (应用控制层/控制器)**
    -   **作用**: 这是整个应用的“大脑”和“指挥中心”。它负责处理用户的操作（比如点击按钮），调用其他模块（如 `log_service`）来完成具体的任务，并更新界面（通过 `ui_builder`）向用户展示结果。
    -   **设计思路**: 作为胶水层，它连接了用户界面和后台服务。它监听用户的输入，并决定调用哪个服务去处理。这种设计模式（通常称为 MVC 或 MVP 中的 Controller/Presenter）使得业务逻辑更加清晰。

-   **`log_service.py` (日志服务层/业务逻辑)**
    -   **作用**: 封装了所有与“日志发送”相关的核心业务逻辑。例如，如何读取日志、如何格式化、如何通过网络发送给服务器等。
    -   **设计思路**: 将具体的业务功能独立出来。如果未来我们需要改变日志发送的方式（比如从 HTTP 改为 WebSocket），我们只需要修改这个文件，而 `app_controller.py` 和 `ui_builder.py` 基本不受影响。这提高了代码的可维护性和可扩展性。

### `docs/`

存放项目相关的文档，如此文档。

### `.github/`

用于存放 CI/CD (持续集成/持续部署) 的配置。
- **`workflows/release.yml`**: 定义了当代码推送到特定分支时，如何自动打包和发布新版本的流程。

### `rawdata/` & `rawdata_processed/`

-   **作用**: 分别用于存放原始数据和经过处理后的数据。
-   **设计思路**: 将数据与代码分离，是良好的工程实践。这使得数据管理更加方便，同时也避免了将大型数据文件提交到 Git 仓库中。

### `config.py`

-   **作用**: 存放应用的配置项，例如服务器地址、端口号、默认用户名等。
-   **设计思路**: 将易变的配置信息从代码中分离出来。当需要修改这些配置时，我们只需要修改这个文件，而不需要去翻找和修改业务代码，降低了出错的风险。

### `main.py`

-   **作用**: 整个应用程序的入口点。
-   **设计思路**: 它的任务非常简单：初始化并启动应用。它会创建应用实例，调用 `app_controller` 来开始运行，是所有代码执行的起点。

### `requirements.txt`

-   **作用**: 列出了项目所依赖的所有第三方 Python 库及其版本。
-   **设计思路**: 这是一个标准的 Python 项目实践。它保证了所有开发者和部署环境都能使用完全相同的依赖库，避免了因版本不一致导致的问题。通过 `pip install -r requirements.txt` 命令可以一键安装所有依赖。

## 总结

整个项目遵循了“关注点分离”（Separation of Concerns）的设计原则：

-   **界面 (`ui_builder.py`)**: 只关心长什么样。
-   **逻辑 (`app_controller.py`, `log_service.py`)**: 只关心做什么。
-   **配置 (`config.py`)**: 只关心怎么配置。
-   **入口 (`main.py`)**: 只关心如何启动。

这种结构使得代码更容易被理解、测试和维护。即使是新手，也可以通过理解每个模块的单一职责来快速上手。
