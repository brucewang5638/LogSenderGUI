# 监管平台日志发送及事件校验工具 - 用户手册 📖

欢迎使用本工具！它旨在简化两项核心任务：持续发送日志文件和验证API返回的事件列表完整性。

## 1. 📝 简介

本工具是一个桌面应用程序，提供了两个主要功能，分别位于不同的选项卡中：

- **日志发送** 📤: 监控指定目录下的日志文件，并将它们通过UDP和HTTP两种方式发送到指定服务器。
- **事件校验** ✅: 向一个API端点发送请求，获取事件列表，并与一个可配置的“标准事件全集”进行比对，找出缺失的事件。

应用底部有一个共享的 **日志区域** 📜，会实时显示所有操作的状态、成功信息和错误提示。

## 2. 📤 日志发送

此选项卡用于模拟客户端持续不断地发送日志。

![主界面-日志发送](./img/1.png)

### 2.1. 目录设置 📁

- **原始日志目录**:
  - **功能**: 指定存放原始日志文件（通常是`.log`文件）的目录。
  - **操作**: 点击`浏览...`按钮选择一个目录。选择后，程序会自动在同级目录下创建一个名为 `[原目录名]_processed` 的目录。
- **已处理目录**:
  - **功能**: 用于存放已被程序成功处理并发送过的日志文件。
  - **操作**: 该路径通常由程序自动生成，当然你也可以通过`浏览...`按钮手动指定。

### 2.2. 服务配置 ⚙️

这里配置日志接收服务器的地址。所有配置的默认值均可在 `config.yml` 文件中修改。

- **本地日志 (UDP)**:
  - **IP地址**: 接收UDP日志的服务器IP。
  - **端口**: 接收UDP日志的服务器端口。
- **流量日志 (HTTP)**:
  - **URL**: 接收HTTP POST请求的完整API端点地址。

### 2.3. 控制按钮 ⏯️

- **开始处理**:
  - 点击后，工具将启动一个后台服务，持续监控“原始日志目录”。一旦发现新日志，会立即处理并发送，然后将其移入“已处理目录”。
  - 启动后按钮会变为不可用状态，直到点击“停止处理”。
- **停止处理**:
  - 点击后，后台监控服务将安全停止。
- **测试发送**:
  - **功能**: 用于快速测试与服务器的连通性。
  - **操作**: 点击后，程序会生成两条预定义的模拟日志，分别通过UDP和HTTP发送到当前配置的地址。你可以在底部的日志区域查看发送是否成功。

## 3. ✅ 事件校验

此选项卡是一个灵活的API请求工具，专门用于校验事件列表的完整性。

![主界面-事件校验](./img/2.png)

### 3.1. 请求配置 🛠️

界面的左侧是完整的请求配置区。

- **请求URL**: 目标API的完整地址。
- **请求方法**:
  - `GET`: 用于从服务器获取数据。
  - `POST`: 用于向服务器提交数据，通常需要配合“请求载荷”使用。
- **Token/Cookie**:
  - **功能**: 用于需要身份认证的API。
  - **操作**: 将你的认证令牌（如 `TOKEN ...`）或完整的Cookie字符串粘贴于此。程序会将其加入请求的 `Cookie` 头中。
- **请求载荷 (JSON)**:
  - **功能**: 当使用 `POST` 方法时，在这里输入请求体。
  - **注意**: 内容 **必须** 是严格的JSON格式。
- **开始校验**:
  - **功能**: 所有配置完成后，点击此按钮发送请求。
  - **操作**: 程序将根据你的配置发送HTTP请求，获取响应后，解析其中的事件列表，并与“标准事件全集”比对。

### 3.2. 校验结果 📊

界面的右侧是校验结果显示区，它会清晰地展示本次校验的结果：

- **统计信息**: 包括从URL中成功获取的事件数量和缺失的事件数量。
- **缺失列表**: 如果存在缺失的事件，会在这里逐条列出它们的名称。

## 4. 🔧 全局配置 (`config.yml`)

![全局配置](./img/3.png)

本工具的大部分默认行为都可以通过修改项目根目录下的 `config.yml` 文件来自定义，无需改动代码。

- **`log_sender`**:
  - `http_url`, `udp_ip`, `udp_port`: “日志发送”功能的默认服务器地址。
- **`event_validator`**:
  - `event_list_url`: “事件校验”功能的默认请求URL。
  - `default_token`: 默认的Token/Cookie值。
  - `default_payload`: 默认的JSON请求载荷。
- **`complete_event_list`**:
  - **非常重要** ✨: 这里定义了用于比对的“标准事件全集”。
  - 你可以根据实际需求，直接在此处 **增、删、改** 标准事件的名称。每次程序启动时，都会加载这个列表作为比对的基准。
